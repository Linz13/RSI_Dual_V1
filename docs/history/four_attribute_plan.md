# 四属性 audio-only 递归训练方案

构建状态：用户已确认构建，目录命名为 `Caption/DualRSI_Train_V6_AudioOnly4Attr`。实现和运行说明见 [V6 README](DualRSI_Train_V6_AudioOnly4Attr/README.md)。代码与 CPU 验证已完成；真实 GPU smoke 和正式训练须在 GPU 服务器执行。本文保留设计与讨论细节，实际运行配置以 V6 的 `configs/v6.yaml` 为准。旧 V5 代码与运行任务未修改。

最新确认：扁平五字段 JSON 与现有枚举；四属性等权精确匹配；采用本文格式分公式，初始重建/格式权重 0.9/0.1；内容错误率 <=10%；TTS SFT 不增加属性最低分门槛。

本次提交的运行配置：group=8；Captioner 与 TTS 推理 batch 分别以每卡 8 为目标，GPU smoke 不适合则独立回退为 4；Captioner GRPO 重放 microbatch 保持 1；每轮先运行本地 ASR，仅为内容合格的重建音频调用属性裁判。另建议继承 10 轮、现有学习率/LoRA，使用下文明确的同分与异常处理规则。它们均尚未进行新框架 GPU 验证。

## 1. 已确定的总体方向

只保留这一条闭环：

```
原始音频 a
  → MiDasheng 采样 K 条 caption（本稿配置 K=8）
  → TTS 分别合成重建音频
  → 本地 ASR 检查最终音频内容
  → 内容合格者进入固定四属性评审；内容不合格者重建奖励为 0
  → Captioner GRPO
  → 选出合格的伪配对，TTS SFT
  → 下一轮使用更新后的两个模型，重新采样
```

- 可训练 Captioner：MiDashengLM-7B-1021-BF16。
- 可训练 TTS：Qwen3-TTS-12Hz-1.7B-VoiceDesign。
- Caption 只保留转录文本、性别、音高、情绪类别、情绪强度。
- 不再输出 language；TTS 内部使用 `Auto`，生成和 SFT 条件保持一致。
- 删除 caption-only loop、TTS GRPO、Captioner cycle SFT、两模型 paired anchor；不额外加入监督 warmstart。
- Captioner 仅做 GRPO；TTS 仅做本闭环产生的伪配对 SFT。
- 不将中间 caption 与原音频参考属性/参考转录比较，不给中间 caption 正确率奖励。语义反馈来自最终重建音频。
- 从两个 base 模型建立独立新 run，不接着已有 V5 adapter 训练，便于区分新旧方案。

迭代希望发生的作用是：更好的 Captioner 提供更合适的 TTS 训练条件，更好的 TTS 提供更有区分度的重建反馈。这是需要实验验证的假设；两个模型都更新不等于已经证明 RSI 有效。

## 2. 数据组织

将原来的三个训练池统一恢复为原始真实音频池，不把旧 caption-only 样本合成为“原始音频”。

本次按现有清单、音频文件和 1.2–30 秒时长限制重新检查：

| 原数据池 | 条数 | 原始音频找到 | 通过现有时长限制 |
|---|---:|---:|---:|
| paired | 39 | 39 | 39 |
| audio-only | 184 | 184 | 184 |
| caption-only | 196 | 196 | 188 |
| 合计 | 419 | 419 | 411 |

419 个样本 ID 不重复。旧 caption-only 清单没有直接暴露音频路径，但能通过原始标注清单的 sample_id 找回 `training_data/audio` 下的真实音频。另 8 条是时长不合要求；因此建议第一版沿用现有规则，使用 411 条候选训练音频。

411 是音频层面可用数，不等于每轮 411 条都会产生 SFT 或 GRPO 更新：参考转录缺失、全部参考属性 unknown、候选失败或同组奖励平分都可能进一步减少有效更新。

每个音频预先保存：ID、音频路径/哈希、固定参考转录、固定四属性、已知属性掩码、标注来源与版本。训练音频清单与独立评测集核对，不能因为合并训练池而引入评测音频。

原先 paired 样本的人工 caption 不作为监督目标送入训练；它们的音频按普通 audio-only 样本处理。已有可靠标注可以作为评审参考，但不能作为 Captioner 输出答案或 TTS 的 GT 条件。

执行前要求参考转录非空且至少一个参考声音属性已知；不满足者记录为参考数据不足，不临时用当前 Captioner 生成参考答案。最终训练清单、参考缺失原因和实际条数单独导出。训练使用的固定参考标签可以来自自动专家，不将它们宣称为全部经过人工核验的真值。

## 3. 五字段 caption（格式与枚举已确定）

采用一个扁平 JSON 对象，减少嵌套结构负担：

```json
{
  "transcript": "今天下午三点开会。",
  "gender": "female",
  "pitch_level": "high",
  "emotion": "happy",
  "emotion_intensity": "medium"
}
```

沿用现有枚举，不同时改变类别定义：

| 字段 | 允许值 |
|---|---|
| transcript | 文本；非空且不是缺失标记才可用于合成 |
| gender | male / female / unknown |
| pitch_level | low / medium / high / unknown |
| emotion | neutral / happy / sad / angry / fearful / surprised / disgusted / other / unknown |
| emotion_intensity | none / low / medium / high / unknown |

`other` 是明确的其他类别，`unknown` 是无法判断，不能互换。emotion2vec 原始标签到这些枚举的映射需要固定并检查；服务错误、无有效输出不得经兜底映射变成一个确定的 `other`。

中间 caption 仅做执行所需处理：解析完整 JSON、检查重复键与字段类型、NFKC/空白/枚举大小写规范化、忽略多余属性、丢弃无法安全映射的字段。`Happy` 可规范成 `happy`；不能凭猜测把一个任意词修成 happy。

保持 V5 对部分属性的容忍：不必四项全部已知；unknown、缺失或非法属性不写入 TTS 指令。只要生成的 transcript 可用，允许用剩余属性继续闭环；没有有效声音属性时，使用不额外指定声音属性的通用朗读指令，并单独统计这种情况。

内部逻辑规则建议暂沿用 V5：例如同一 caption 为 neutral + high 强度时，丢弃冲突的强度条件并记录，不猜测改成 low。这不使用原始音频标签。该规则属于具体实现建议，可与枚举定义一起讨论。

规范化仅作用于执行副本。Captioner GRPO 必须训练实际采样的原始 token 序列及其 old/ref log-prob，不能拿“修好后的 JSON”替换采样轨迹。

## 4. 固定打标方案（已确定）

| 信息 | 打标模型 | 用途 |
|---|---|---|
| 性别 | Qwen3.5-Omni-Plus | 四属性重建评分 |
| 音高 | Gemini-3.1-Pro-Preview | 四属性重建评分 |
| 情绪类别 | emotion2vec-plus-large | 四属性重建评分 |
| 情绪强度 | Qwen3.5-Omni-Plus | 四属性重建评分 |
| 转录文本 | Qwen3-ASR，现有 1.7B 部署 | 最终音频内容检查 |

Qwen3.5 一次请求返回性别和情绪强度；Gemini 只要求音高。裁判不提供参考答案，只听待标注音频按固定提示输出。四项全部使用单模型，不再进行多模型一致性投票。

模型名称、提示、枚举映射、API 服务商和本地权重版本在本实验内固定，沿用已授权的凭据读取方式，日志不写密钥。需要变更评审配置时使用新缓存身份，不能让同一轮混入不同规则的分数。

原始音频和重建音频使用同一固定属性规则。原始参考在开始训练前准备并冻结；已有经过核验的参考转录优先使用，否则由 Qwen3-ASR 得到自动参考并记录来源。重建音频逐轮打标，缓存以音频哈希及模型、提示、解析规则版本确定身份。

不再调用 Qwen3-Captioner、Step-Audio、韵律/停顿 GPT-5.5 文本评审以及已删除属性的其他专家。GPU 打标只需要实际保留的 ASR 和情绪模型。模型能力图支持选择这些裁判，但图中 primary score 不能直接当作这 411 条数据上的实测准确率。

## 5. 最终重建音频的内容门槛

这是已接受的规则：**规范化错误率 <= 10% 合格，包含等于 10%。**

比较两端：原始音频的可靠参考转录 t，以及最终重建音频的独立 ASR 输出 t_hat。不比较中间 caption 的 transcript 与 t，也不能在合成时把中间 transcript 偷换成 t。

建议规范化使用固定规则：Unicode NFKC、英文小写、去无关标点、规范空白、明确等价的数字书写转换。不删除否定词、数字或单位，不通过 LLM 意译消除真实内容差异。

- 中文用 CER，英文用 WER。
- 分词规则由参考文本确定；混合文本建议汉字按字、英文按词，单独记为混合错误率。
- 去掉 schema 的 language 不影响内部按文本选取比较规则。

```
E = (替换数 + 删除数 + 插入数) / 参考单位数
G = 1，若 E <= 0.10；否则 G = 0
```

例如 20 个参考汉字允许累计 2 次编辑错误，3 次不通过。很短的句子会更严格；第一版不自动增加“至少允许错一个字”的例外。原始错误率即使大于 1 也应保存。

参考非空、ASR 成功但识别为空：不合格。参考为空、ASR 超时或服务异常：不可评分，进入重试；不能作为模型说错的 0 分。

门槛只约束内容基本一致，并不保证完全一致。它也不要求声音、音色或波形逐点相同。

本稿新增的省费调度建议：**先 ASR、后属性打标**。G=0 时不再请求 Qwen/Gemini，也不必运行 emotion2vec；直接记录重建奖励为 0、属性分未计算。这个短路与既定奖励公式等价，但无法再得到这些被拒音频的四属性诊断分数。

具体状态必须区分：`content_failed` 表示 ASR 已完成且 E>0.10，重建分为 0；`attribute_not_requested_content_failed` 表示有意省略属性评审，R_attr 为 null；`evaluation_pending` 表示 ASR/评审尚未成功，reward 为 null。不能写成“属性四项都错”，也不能把服务失败当作内容不合格。

## 6. 四属性重建奖励（等权精确匹配已确定）

对于一条原始音频，把参考标签已知的属性组成集合 M；同组 K 条候选共用这一集合。

```
s_j = 1，若重建音频属性与原始音频参考属性一致；否则为 0
R_attr = sum(s_j for j in M) / len(M)
R_reconstruction = G * R_attr（G=1 时须有有效 R_attr；G=0 时直接取 0）
```

第一版四项等权、枚举精确匹配。四项参考全已知时，原始属性分只有 0、0.25、0.5、0.75、1。音高/情绪强度相邻等级不给部分分，需要记录平分比例。

| 情况 | 建议处理 |
|---|---|
| 原始某属性 unknown | 从 M 排除，该组所有候选分母相同 |
| 重建音频某属性 unknown / 缺失 / 无法安全映射 | 该项 0 分，不缩小分母 |
| 原始四属性全部 unknown | 没有属性参考，排除对应语义训练并记录 |
| 评审请求整体失败或响应损坏 | 待重试，不冒充真实 0 分 |
| 中间 caption 某属性 unknown | 仅不作为 TTS 条件；最终仍按原始 M 评分 |

因此不能因为中间只填了两个属性，就只按那两个属性算重建分。不过，TTS 的默认声音或一次采样确实可能偶然恢复省略的属性；最终分数仍无法保证中间 caption 每个字段都正确。按已确定原则，不增加中间 GT 判断来消除这种可能性，而是保留候选/指令/音频供诊断。

## 7. 格式奖励与最终 Captioner reward（公式与初始权重已确定）

第一版初始使用固定权重；本稿不加入自动衰减调度：

```
R = 0.9 * R_reconstruction + 0.1 * F
```

不加入之前讨论的 TTS likelihood/loss、反事实项、冻结基模奖励项、cosine 或 SpeechBERTScore；这些仍属于候选实验，不是本版已确定的奖励组成。GRPO 内部的 KL 正则保留，它与被移除的冻结模型“奖励项”不同。

格式分采用 V5 的结构，分母改成 5：

```
F = 0，若不能解析为完整 JSON 对象
F = 0.5 + 0.5 * n_legal / 5，否则
```

`n_legal` 是实际出现且类型/枚举合法的目标字段数，多余字段不增加分母或分子。安全大小写规范化后的值可计入。四个属性的 unknown 是合法格式，可计格式分；这不代表获得该属性语义分。transcript 为空或缺失标记不计为有效文本字段。不能先补齐 unknown 再按“全字段齐全”打格式分。

内容不合格时，语义分为 0，但仍可得到最多 0.1 的格式分；这样可以保留初期格式学习信号。Captioner 自身输出完全无法执行时，同样没有语义分，但在采样轨迹有效的情况下可按格式规则参与比较。技术性 TTS/评审失败必须走重试状态。

四属性参考全已知、格式全部正确时的例子：

| 候选 | 内容合格 | 属性匹配数 | F | 最终 R |
|---|---|---:|---:|---:|
| A | 是 | 4/4 | 1 | 1.000 |
| B | 是 | 3/4 | 1 | 0.775 |
| C | 否 | 4/4 | 1 | 0.100 |
| D | 是 | 2/4 | 1 | 0.550 |

格式权重 0.1 不等于只贡献 10% 的梯度：GRPO 会进行组内归一化。若一组重建分全部相同，该组的 reward 差异仍可能完全来自格式。本稿先记录“只有格式产生区分的组数/更新占比”，不额外限制这类组或加入格式权重衰减。

## 8. 一轮具体如何执行

设本轮开始时参数为 C_r、T_r。

1. 读取固定音频池和参考缓存，按音频组成组。
2. C_r 对每个音频随机采样 K 条五字段 caption；保存原文、token、概率、seed 和解析结果。
3. 用每条 caption 自己的 transcript 作为 TTS text，用可用四属性生成 instruct；TTS 内部 language=Auto，不输入 reference audio。
4. T_r 为每条可执行 caption 合成一次音频。411 条全部可执行时，K=4 最多生成 1,644 条音频，K=8 最多 3,288 条。初版不对每条 caption 重复合成多次求均值。
5. 本地 ASR 先评估最终音频；只有内容合格者再由固定四属性裁判打标。计算门槛、重建分与格式分，保存逐项标签、错误率、分数和失败/未请求原因。
6. 按每个原始音频的组内 reward 更新 Captioner，得到 C_(r+1)。
7. 从本轮候选中形成 TTS 伪配对，做一轮 SFT，得到 T_(r+1)。
8. 两模型 checkpoint 与本轮状态完整落盘后提交 round；下一轮用更新后的两个模型重新采样，不复用旧候选来冒充新一轮。

收集候选和评分期间不更新 C_r/T_r，不在同组或同轮中途替换 TTS 版本。更新顺序沿用先 Captioner 后 TTS，但 TTS SFT 数据仍来自本轮收集的固定候选。

Captioner GRPO 是组内相对比较：奖励高于均值的输出得到提高概率的信号，低于均值的输出相反；不是把最高分 caption 直接当 GT 做 Captioner SFT。

本稿采用的组处理建议：至少 2 条轨迹有效、反馈可用的候选才能形成相对更新；已确认内容不合格的候选以低奖励参与，不全部删掉；完整组奖励相同则跳过该组 GRPO 更新。技术评测失败优先补齐原候选，不能只留下容易评分的候选悄悄改变组。

每个评测任务默认最多 3 次尝试（含首次），失败时采用有界退避并持久化错误。可继续收集其他组，全部收集后补齐未完成任务；仍失败则保存可恢复断点并明确报告本轮未完成，不将技术失败组自动按 0 分、静默删除或提交为已完成轮次。完整 JSON 中个别非法枚举经安全规范化仍无法映射时，只将该字段记为 unknown，其余合法字段可用；整个响应不可解析、流未结束或模型不符时仍属于未完成评审。

## 9. TTS SFT：选择什么，GT 是什么

首先限定内容错误率 <=10%、属性可评分且 TTS 条件可用的候选，然后按 R_attr 选择最高者。**已确定不增加属性最低分门槛**，取消此前 R_attr>=0.75 的建议。即使所有符合上述条件的候选属性分都较低（包括都为 0），仍按既定 top1 规则选择；记录实际分数，不把相对 top1 自动称为高质量。

没有合格候选就不为该音频生成 SFT 记录。每个原始音频每轮最多一条 SFT 记录，最多 411 条；不补入原来的 39 条 paired anchor。

同分处理建议：先选内容错误率更低者；仍同分用固定候选顺序确定。只使用最终音频证据，不比较中间 caption 与原始标签。

Captioner GRPO 和 TTS SFT 的可用性分别判断：即使一组所有候选奖励相同、GRPO 无更新信号，只要存在上述内容合格且可评分的候选，仍可以按同分规则生成 TTS SFT 记录。

训练记录：

```
输入 text：选中 caption 的 transcript
输入 instruct：选中 caption 的可用四属性
内部 language：Auto
GT：原始真实音频的 codec token
```

GT 不是刚刚生成的重建音频，也不是原始人工 caption。仅在监督目标侧读取原音频 codec，不把原音频作为 VoiceDesign 的声音参考条件。teacher forcing 使用目标音频过去的 token 来预测后续 token。

建议保持当前 TTS SFT 目标：

```
L_TTS = L_主码本 + 0.3 * L_子码本
```

继续沿用现有有效音频 token mask 和子码本聚合实现；不改成两段波形的 cosine。某个声音条件 unknown 只影响输入 instruct，不能把 codec 中所谓“对应属性的 token”单独找出来屏蔽。

10% 内容门槛允许少量文本错误，因此即使通过筛选，这种伪配对仍可能存在轻微文本/原音频不一致；同时，高重建分也不严格保证中间声音条件正确。第一版按已确定的统一 10% 内容门槛执行，不额外收紧 SFT 门槛；记录这些限制，不能默认声称伪配对完全准确。

## 10. 参数与资源调度（建议默认值）

| 项目 | 建议 |
|---|---|
| 轮数 | 10 轮，每轮新采样；不等于一次性训练 10 epoch |
| 组大小 | 本稿配置为 8 条 caption / 原始音频 |
| Captioner GRPO | 每轮 1 epoch，lr=1e-6，clip=0.2，KL beta=0.02，grad clip=1 |
| TTS SFT | 每轮 1 epoch，lr=2e-6，子码本权重 0.3 |
| Captioner LoRA | 沿用 r=4、alpha=8、dropout=0 与现有目标模块 |
| TTS LoRA | 沿用 r=16、alpha=32、dropout=0.05 |
| 格式/内容采样 | 保留随机采样；不以重复的贪心输出代替 K 条随机候选 |
| Captioner 生成上限 | 先保留 384；检查长转录截断后再调整，不能仅因字段少就压得过低 |
| TTS 生成上限 | 先沿用现有 512；统计是否达到上限及音频是否截断 |
| 推理 batch | Captioner 采样与 TTS 合成分别尝试每卡 8；真实 smoke 检查显存、吞吐和回退，不适合时各自降为 4 |
| Captioner GRPO replay microbatch | 保持当前 1，不随推理 batch 自动增加；group=8 可分批处理 |
| GPU 规模 | 配置支持 4/8 卡；每卡预算按实际空闲显存设置 |

本版无需 TTS GRPO 的 old/ref codec 概率重放，也无需冻结 Captioner 作为重建奖励裁判。Captioner GRPO 本身的采样概率一致性与 KL 仍必须保留。

调度建议复用已验证的分片、按长度平衡、结果缓存、断点恢复。各卡分片生成完成并释放模型后，分阶段运行本地 ASR/emotion2vec，再进入训练；不默认让多个本地大模型同卡常驻。API 对已经通过 ASR 的音频有界并发，可以与剩余 ASR/情绪任务重叠，不对尚未通过 ASR 的音频提前发送付费请求。本稿先沿用当前 API 并发 4，限制与失败率在日志中可见；可独立配置，不把 GPU 数量直接作为 API 并发数。

原始参考打标通常只做一次，411 条对应最多 822 次属性 API 请求，不含缓存复用和重试。K=4 每轮最多 1,644 条重建音频、3,288 次属性 API 请求；K=8 则最多 3,288 条音频、6,576 次属性 API 请求（每条一次 Qwen3.5、一次 Gemini），均不含重试。采用先 ASR 后属性评审时，设内容合格音频数为 N_pass，新增属性请求上限为 2*N_pass，缓存命中还可以减少实际请求。

API 费用不能按属性个数减少比例估计，也不能把请求倍数直接当账单倍数：音频输入、提示、输出/思考 token、服务商单价和重试都会影响费用。本次构建须保存每次响应的 usage、模型和请求状态，区分参考准备与各训练轮次，便于后续按实际结算规则统计，不虚报人民币金额。

K 从 4 增到 8，候选生成、逐候选评分和 Captioner GRPO 重放的工作量约翻倍；每音频仍只选一条 TTS SFT，SFT 记录数上限不变。增加组大小不改变四属性分数的离散档位，也不保证避免同分。

旧 V5 在 184 条 audio-only、196 条 caption-only、K=4 下，两分支 TTS 候选总上限为 1,520；新方案 K=8 为 3,288。删除 TTS GRPO、多属性打标及一个 loop 会节省计算，但音频池与组大小扩大又增加计算，不能预先断言总时长大幅下降。

现有 MiDasheng worker 在批量采样与单条概率重放不一致时，会记录 trajectory_mismatch 并在当前进程回退串行。后续实现需核验 batch=8 的实际生效情况和概率一致性，不能以放宽轨迹校验或替换行为概率来掩盖问题。相关统计中写死为 4 的 group_size_preserved 也应与真实 K 一致。

group 大小与推理 batch 独立：K=8、batch=4 可以分两批完成一组；batch=8 不会把组大小变为 64。当前为各卡分片/模型副本执行，能否容纳 batch=8 要看单卡峰值，不能相加八张卡的显存当作单卡预算。

## 11. 断点、日志与评测

新版本独立 schema/reward/cache 版本号和 run 目录；不覆盖 V5。只有音频哈希、模型版本、提示、解析规则都匹配的旧打标结果才可复用；删除旧奖励及反事实校准路径，不混用完整 schema 的轨迹或分数。

每轮至少输出：

- 实际参与音频数；参考已知属性数量和类别分布。
- 原始 JSON 解析成功率、规范化情况、有效声音条件数、全 unknown 比例。
- 最终音频 CER/WER 分布、<=10% 通过率。
- 内容合格音频的各属性匹配率与 unknown 率；内容不合格者明确标为属性未评审，不混入属性准确率分母。
- 同组重建分极差、平分比例、最高分与次高分差距。
- GRPO 有效组数、仅格式区分组数、跳过原因与实际优化步数。
- TTS SFT 入选数、属性分、内容错误率、已知参考数量及拒绝原因。
- API/ASR 技术失败与模型真实失败分开统计；采样/打标/GRPO/SFT 各阶段耗时与 batch 回退。
- 实际 API 请求、重试、缓存命中与 token usage；先 ASR 后评审节省的请求数。

独立评测使用固定未参与训练的音频/文本条件，比较 base 与各完成轮次：Captioner 的四属性与转录能力、TTS 的四属性遵循和内容正确性，并保留音质核查。训练 reward 提高本身不是泛化提升的证据。

如果继续使用旧三个 Captioner benchmark 或 TTS DSD，全量结果可以作为迁移表现；新方案只训练四属性，不能把四属性平均分直接与旧全属性总分混为一个指标。

方法描述应明确：这是固定外部裁判辅助的单条音频重建闭环，联合迭代 Captioner 与 TTS；去掉 paired anchor 并不意味着无外部监督。若要证明“递归更新 TTS”比固定 TTS 更有效，后续可设计固定 TTS 对照，但不把新增完整消融作为本次方案讨论的前置条件。

## 12. 确认后的构建范围与交付

新框架目录为 `/data/L202500147/Caption/DualRSI_Train_V6_AudioOnly4Attr`，以当前 V5 FastResume 的 worker、LoRA、概率重放及断点能力为基础，新建独立单分支调度入口。启动脚本为 `scripts/run_v6.sh`，命令见 V6 README。

构建顺序：

1. 新数据清单与五字段 schema/render/parser：恢复真实音频路径，去重与时长检查；建立独立 schema 版本；运行输入不得夹带原始参考答案。
2. 原始参考准备与四属性评审服务：固定裁判身份，接入 Qwen3-ASR 内容门槛；只启用所需模型；实现 API usage 与缓存记录。
3. 奖励与选样：实现固定参考掩码、等权精确匹配、先 ASR 后评审、0.9/0.1、无属性最低门槛的 SFT top1；处理平分和技术失败。
4. 单分支调度与训练数据构造：每轮采样→评分→Captioner GRPO→TTS SFT→提交；删除旧 caption-only/anchor 的隐式依赖；每轮两个模型版本完整关联。
5. 运行与恢复：提供 CPU preflight、数据/参考准备、GPU smoke、train、resume、状态看板入口。新配置分开控制 group、两种推理 batch、GRPO microbatch、GPU 列表和每卡显存预算。
6. 验证与交付：先完成 CPU 可执行的关键逻辑验证，再交付另一台 8 卡 H100 上的 GPU smoke 和正式训练命令，保持前台运行，适合 tmux。

CPU 验证重点是会改变训练含义的边界：0.10 恰好通过；参考与候选 unknown 的分母不同；内容错误保留格式分但不入 SFT；无属性门槛时 0 分 top1 仍按规则入 SFT；平分组跳过 GRPO 但不必跳过 SFT；未评分不同于真实 0；原始采样 token 与执行副本分离；SFT GT 为原始 codec；配置不得启动 anchor/其他 loop。

GPU smoke 覆盖 group=8、较长音频、两模型推理 batch=4/8 对比、真实批量与概率重放一致性、每卡峰值显存；确认至少一个有效 GRPO 更新与一个 TTS SFT 更新发生、adapter 可重新加载、断点可续接。若真实样本全平分或没有内容合格候选，明确报告缺少对应更新验证，不将阶段正常退出冒充训练更新已验证；再扩大 smoke 样本覆盖。新框架整体通过后再启动正式轮次。

## 13. 本次确认的边界

已确定规则保持：单条 audio-only loop；四属性加转录；扁平 JSON 与现有枚举；不检查中间 caption GT；合并原始音频；无 paired anchor；固定打标模型；四属性等权精确匹配；已定格式公式与初始 0.9/0.1；统一内容错误率 <=10%；TTS SFT 不加属性最低分门槛。

本次提交整体确认的是：group=8、推理 batch=8 为目标且 GPU smoke 不适合则降为 4、GRPO 重放保持 1、先 ASR 后付费属性评审、10 轮及其余继承参数、同分/异常处理和上述构建交付范围。没有自动加入 loss/cosine 奖励、格式预热或监督 anchor，也没有启动训练或收费打标。
