解释与边界：

- V4 并非没有格式奖励：至少两个 semantic_valid 候选时使用重建语义奖励；否则有足够可回放候选时使用 schema_progress。
- raw_schema_valid、安全准入、完整 semantic_valid 是不同口径。旧语义准入还依赖 ASR、likelihood、反事实及冻结 anchor 分数，不能将所有语义拒绝归因于格式。
- r0-r3 的格式组占比为 76.6%-84.8%；这是训练组成，不是格式奖励有效性的因果实验。格式训练已经占较大比例，不能凭低通过率断言应进一步提高其权重。
- r4 附近另有解析器异常与隔离恢复记录，后续结果不能未经区分就解释成初始格式能力。表格忠实保留原始输出，不以修复后的解析规则重算。
- 新部分字段准入能容忍缺失/无效的可选字段，但并不自动修复破损 JSON、重复键及无法确定归属的内容。
- 格式规则可鼓励可解析 JSON、正确层级/键名/类型和值域；合法 unknown 应与其他合法枚举得到同样的格式评价，不能把非 unknown 数量当成语义正确性。
- 格式组若统一将 reward 乘小系数，随后组内标准化可能抵消此缩放；限制格式训练影响需考虑组采样比例或标准化后 loss 的权重。
- 推荐首版保留适配部分字段准入的格式兜底；已能形成重建比较的组用属性 reward，TTS SFT 只在可用且完成评价的候选中按重建分数选样。

逐轮来源路径和 SHA-256 见 evidence.json。这里没有实施上述训练建议。
