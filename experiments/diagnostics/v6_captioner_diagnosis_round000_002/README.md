# V6 Captioner 前三轮诊断

范围：`DualRSI_Train_V6_AudioOnly4Attr/runs/midasheng_v6_8gpu_run01` 的 round_000–002。只读取既有数据，未修改训练、未调用 API、未运行 GPU。统计脚本为 analyze.py，结果为 analysis.json。

**解释边界：**中间 caption 的“正确”在本报告中指与本次固定参考标签一致，并非新的人工作业或独立测试集真值。这是离线诊断，不是新增中间 caption 奖励。第 r 轮收集使用更新前的模型，因此三次收集对应 base、第一轮和第二轮 checkpoint；不能把 round_002 的采样统计称为第三轮更新后的准确率。

## 1. 可靠的最终音频裁判，不保证 caption 的语义正确性

训练评分路径为原音频→Captioner→TTS→最终音频打标。Captioner 的属性值不直接与参考标签比较。重建分高可以来自 TTS 默认行为、文本所带来的情绪、随机生成或评审波动，而不必来自 caption 正确描述了原音频。

第三轮中，在某属性的最终音频重建得分为 1 的候选内，中间 caption 同一属性也与参考一致的比例：

| 属性 | 重建正确的候选数 | caption 同属性也正确 | 比例 |
|---|---:|---:|---:|
| 性别 | 868 | 845 | 97.35% |
| 音高 | 274 | 59 | 21.53% |
| 情绪类别 | 372 | 187 | 50.27% |
| 情绪强度 | 631 | 120 | 19.02% |

其余候选含错误值或 unknown，不能把比例直接解释为 judge 错误率。性别的间接信号明显比另外三个属性可靠。

实例：`random440_expressivespeech_067::4` 与 `::5` 的 TTS 输入完全相同：female、low pitch、neutral、low intensity，转录也完全相同。原音频参考为 female、high pitch、neutral、none intensity。两条最终重建分分别为 0.5 和 1.0，总奖励分别为 0.55 和 1.0。后一条 caption 虽然音高和强度都不符合参考，仍得到满分。

第三轮共有 82 个同组内完全相同 TTS 输入的重复集合，其中 41 个集合出现不同重建分；最大跨度为 0.75。这是已有重复样本中的观察，并非随机抽样得到的总体方差估计；尚未分离 TTS 随机性与 judge 波动。

对可送入 TTS 的候选，按组中心化后，“caption 四属性参考一致率”与“最终总奖励”的相关系数前三轮约 0.121、0.093、0.101。它只作为辅助描述，不能当作因果估计。

## 2. 格式和内容问题大幅减少属性学习机会

| 收集轮次 | 候选数 | 成功送 TTS | 内容通过 | GRPO 更新组 | 仅格式区分的组 |
|---|---:|---:|---:|---:|---:|
| 第一轮 | 3288 | 2476 | 991 | 388 | 159 |
| 第二轮 | 3288 | 2525 | 980 | 386 | 164 |
| 第三轮 | 3288 | 2628 | 1041 | 386 | 150 |

第三轮仅 31.66% 的全部候选进入四属性评分；150/386=38.86% 的更新组只能依靠格式分区分候选。另有 175/411 个组完全没有通过内容检查的候选，仅 171/411 个组存在至少两个内容通过且重建分不同的候选。

`reward_v6.py` 对总奖励做组内标准化。在仅有格式差异的组内，0.1 系数会在减均值、除标准差时抵消。因此“格式权重 0.1”不等于“所有更新中格式只影响 10%”。精确梯度贡献还取决于 token 梯度等因素，不能直接用组比例替代。

第三轮内容失败 1587 条中，1474 条中间 caption 的转录本身也未达到同一 10% 错误率标准；113 条中间转录已通过而最终 ASR 未通过。此为离线检查，未改变训练门槛；它不能完全区分原始转录误差、TTS 和 ASR 的责任。

## 3. 候选分布没有提供足够的情绪探索

第三轮 2628 条可送 TTS 的 caption 中：neutral 2026 条（77.09%），happy 44 条；音高 unknown 1195 条（45.47%），情绪强度 unknown 1486 条（56.54%）。固定原音频参考中 neutral 为 83/411，happy 为 116/411。

在情绪参考已知的 375 个组中，仅 136 个组至少有一个可送 TTS 的候选情绪与参考一致，即 36.27%；其余 239 个组没有这样的正确情绪候选。8 次采样并非 8 次独立、均衡的属性探索。只有选错与选对两种候选都出现时，才有直接可辨的组内属性对照；其他候选仍可能通过共享参数变化间接受益，但没有保证。

## 4. 音高裁判的有效覆盖率下降

| 收集轮次 | 内容通过音频 | 音高被判 unknown | 比例 |
|---|---:|---:|---:|
| 第一轮 | 991 | 259 | 26.14% |
| 第二轮 | 980 | 479 | 48.88% |
| 第三轮 | 1041 | 562 | 53.99% |

查看缓存，unknown 记录是模型明确返回 unknown，而非字段解析错误。analysis.json 的缓存汇总扫描了当时整个运行缓存（包括其他已存在 scope），故不可当作前三轮分母；本表严格取各轮 summary。

参考已知时，预测 unknown 在当前评分中记 0，参考 unknown 则不进入该属性分母。即使裁判在另一套理解能力实验中准确率高，也不能因此保证在当前提示和合成音频分布下仍然高覆盖、高区分度。需进一步分离音频变化与评审变化，不能仅据 unknown 增长判断 TTS 一定退化。

## 5. TTS SFT 的伪条件可能延续上述偏差

第三轮选中的 236 条 TTS SFT 条件，按参考已知属性计算，caption 与原音频参考一致的比例为：性别 90.68%，音高 19.18%（219 条），情绪 33.80%（216 条），强度 13.98%。不一致含 unknown，unknown 会被 renderer 省略，因此并非所有不一致都是相反条件；但错误的已知属性确实也能被选中。

TTS 仍以原音频作为 SFT 目标。如果选中的条件存在错误，就有可能进一步减弱属性词与音频之间的语义对应；而 TTS 又参与下一轮 Captioner 评分。这是机制风险，尚未通过冻结 TTS 的对照实验证明其实际贡献。单纯提高重建总分门槛不能排除该问题，因为已有错误条件获得满分的实例。

## 6. 参数确实更新，但更新量有限，且存在需验证的反传近似

前三轮 Captioner 各 49 次同步 optimizer step，总计 147 次；每轮 1 epoch、lr=1e-6、LoRA rank=4。参数确实变化，396 个参数张量的八卡同步检查均通过，最大差异 0。

相对轮初策略的日志平均 KL 为 0.000281、0.000336、0.000364。说明采样路径上策略变化较小，不等于模型完全没学，也不能据此直接认定应提高学习率。GRPO mean_loss 接近零会受到组内优势中心化影响，不是没更新的证据。

实现每 16 个生成 token 反向传播一次并 detach KV cache。它保留采样 token 与前向概率的回放，但跨分块的历史梯度路径被截断，不能等同于完整 teacher-forcing 反传。后续属性 token 对历史音频表示的部分梯度路径可能受限；需 GPU 梯度对照才能量化其影响，当前日志不能证明它是 benchmark 停滞的主因。

## 7. Benchmark 本身的解释边界

前三轮 StyleCap 与 base 的正确题数差异分别为 +6、0、-1（总 3112），ParaSpeechCaps 性别第三轮比 base 少 3 题，音高少 1 题（总 140）。现有小差异不能直接认定能力显著下降。

ParaSpeechCaps 音高标签中 112/140 为 high-pitched。base 回答 unknown 103 条、high-pitched 1 条；第三轮回答 unknown 104 条、high-pitched 1 条。极低分数主要对应既有的输出分布与测试标签不匹配，尚未判定是声学判断、提示适配或标签口径的哪一项导致。

训练使用五字段 JSON；ParaSpeechCaps 使用 P0/P1 等选项编号，EmotionTalk 使用中文描述。训练到测试的输出任务不同，必须补充独立留出音频上的同五字段评估，才能区分属性学习与格式迁移。其真值仅用于离线评估，不必加入训练奖励。

## 优先顺序

1. 优先检查固定转录、仅改变一个属性时的 TTS 响应及其重建奖励是否具有正确方向，并重复少量随机种子。该实验可定位条件响应和评审覆盖问题。
2. 调整仅格式组在标准化之后的更新贡献，避免 0.1 名义权重被误当作实际学习贡献上限；保留最终内容检查并排查转录失败来源。
3. 考虑先固定 TTS 做短程 Captioner 对照，减少双方共同变化造成的归因困难；不能把它称为已证实的修复。
4. 用独立留出音频、同五字段提示检查四属性、unknown 覆盖和转录错误率；保持 benchmark 原有口径。
5. 做 KV 分块反传与完整 teacher-forcing 的 GPU 梯度对照，再决定是否改 GRPO 更新实现。
