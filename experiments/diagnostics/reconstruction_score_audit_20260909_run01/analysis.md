# Captioner reward 中 TTS 重建分数：历史产物审计

日期：2026-09-09。用户怀疑多版训练效果不理想与 reward 设计有关，要求查看已有样本的重建分数。本次只做 CPU 文件统计，不生成音频、不调用标注/API、不运行模型、不修改训练源码、配置、checkpoint 或 run 状态。没有执行此前讨论的独立生成诊断，也没有实施新奖励方案。

## 结论

1. 重建分数是主码本平均 log probability 加 0.3 倍子码本平均 log probability。V3/V4 有效候选轮均值主要在 −3.3 到 −3.6；它不是正确率，负值及距离零较远不能证明奖励无效，指数化后也不能直接当成音频重建成功率。
2. 更值得关注的是已有 paired 真配对与单字段反事实的区分能力。固定同一音频，比较原描述和一个改写描述的重建分数：MiDasheng V2 为 206/390 次原描述更高，V3 为 214/390，V4 为 97/195；Qwen V4 为 62/117。当前重建项在这批比较中并未稳定偏好原描述。这支持检查奖励的属性区分能力，不是“数值低”的证明。
3. 重建分数不是常数，组内有差异；V4 MiDasheng 各轮至少两个有效候选的组，其 max−min 中位数约 0.048–0.113。这只能证明有区分信号，不证明排序方向正确。
4. 已存 main/sub 分数、z-score、语义 reward 和 advantage 的 112 项逐轮算术复核通过，最大绝对误差 4.44e−16。它验证了保存值之间的一致性，不能替代 GPU likelihood 正确性审计、人工属性判定或训练收益消融。

- MiDasheng-7B V2 原十轮、V3 十轮、V4 r0–r4；Qwen2.5-Omni-3B V4 四卡 r0–r2单列，不混同模型/卡数。

## 2. 为什么“都很低”不是有效性判据

当前 s=mean(log P_main)+0.3 mean(log P_sub)，不是 0–1 的匹配准确率，通常为负。它同时包含两个经过平均和加权的码本项，不能把 exp(s) 解释为整段音频成功生成概率或标准 perplexity。

进入 reward 前，reconstruction 用该 run 的首轮统计标准化。V4 各轮 z(rec) 均值在 −0.138 到 +0.099 左右，而不是直接把 −3.5 当作负的正确率。随后 GRPO 又做组内 reward 标准化；是否形成正确更新主要依赖组内排序与其可靠性。

同理，分数变高也不足以证明语义变好。固定 paired 正例的均分，V3 从 −3.407079 升到约 −3.36807，V4 到 r4 升到 −3.370849，但 TTS 每轮也在用这些 paired 数据做 SFT。该上升可能包含对已有录音的拟合，不能单独证明对新描述的判断更准确。

## 3. 更直接的现有证据：同一音频的原描述与改写描述

利用已有 `audio_only_sft_confidence_calibration.output.jsonl`，按 source ID 匹配正例与负例。每轮 39 对：正例是 paired 原描述，负例是代码选出的第一个单字段反事实。两者使用同一真实音频和同一轮 TTS，比较的是原始重建值，不是比较两个不同录音的难度。

| 分支 | 原描述重建分数更高 | 比例 | 每轮胜出数范围 |
|---|---:|---:|---:|
| MiDasheng V2 r0–r9 | 206/390 | 52.82% | 15–24/39 |
| MiDasheng V3 r0–r9 | 214/390 | 54.87% | 18–24/39 |
| MiDasheng V4 r0–r4 | 97/195 | 49.74% | 15–24/39 |
| Qwen2.5 V4 r0–r2 | 62/117 | 52.99% | 19–24/39 |

没有将不同版本合并为更大独立样本；r0 多个版本共享相同 TTS 起点及配对评分。以上只作描述统计，不给独立伯努利置信区间，不声称总体语义判断与随机严格等价。

MiDasheng V4 的分数对照：

| round | 原描述均分 | 改写描述均分 | 原−改写平均差 | 原描述胜出 |
|---|---:|---:|---:|---:|
| r0 | -3.407079 | -3.411116 | 0.004037 | 24/39 |
| r1 | -3.402735 | -3.400758 | -0.001977 | 18/39 |
| r2 | -3.393987 | -3.398597 | 0.004610 | 22/39 |
| r3 | -3.384780 | -3.385542 | 0.000761 | 18/39 |
| r4 | -3.370849 | -3.366338 | -0.004511 | 15/39 |

这比绝对值低更有针对性：对已知原描述与构造改写，分数差异小，方向并不稳定。但 paired 原标签与反事实也不是本次独立人工验真的绝对真值，各字段难度/噪声不同；不能把该比例直接称作线上四候选选对率。

CSV 另列 pooled AUROC：纯 reconstruction 大约 0.50，加入 counterfactual/anchor 后的综合 reward 有所不同。跨录音 pooled AUROC 会受到录音难度的影响，不能取代上述同录音比较。综合 reward 的正负例还存在比较集合不对称：正例对最多三个反事实，校准负例只对原正例，因此也不是对原始重建项的单因素验证。

## 4. 不是完全没有信号，也不是只剩重建项

MiDasheng V3 十轮有 431/1840 个语义 GRPO 组；V4 已读五轮为 141/920，其余为格式组。当前模型并非每条候选都由语义重建 reward 更新。V2 十轮只有 1 个语义 GRPO 组，不能把其效果全部归因于重建项数值。

在有至少两个语义有效候选的组中，V4 各轮仅按 reconstruction 选 top-1 与按完整语义 reward 选 top-1 的一致率约 55.8%–84.4%，说明反事实项及 anchor 确实可能改变排序。该一致率没有人类真值，只证明两个排序不完全相同。

小的原始差值不自动意味着无效，因为 z-score/advantage 会放大相对差异；它也不自动意味着有效，若微小差异来自噪声，标准化同样会放大噪声。

## 5. 对当前研究判断的影响

可以说：**已有数据使“当前重建 reward 对目标属性区分不够可靠”成为值得认真考虑的解释。** 不能说：**因为分数约 −3.5，所以 likelihood 方法失败，新的属性匹配 reward 必然更好。**

用户此前决定时间紧，暂不做新生成独立诊断。本次只利用已存在的配对/反事实产物，不要求新增 GPU 测试。若后续实施用户提出的固定打标器属性循环奖励，应作为独立新实验，明确参考伪标签、评分字段、未知值处理及对当前反事实/anchor/标定的影响；本次未实施该改变。
